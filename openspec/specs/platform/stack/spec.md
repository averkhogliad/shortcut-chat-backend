# Platform Stack Specification

## Purpose

Define the language, framework, build, persistence, messaging, observability, and test infrastructure used by the backend.

## Requirements

### Requirement: Language and framework versions

The backend SHALL use Java 17, Kotlin 2.4.21, Spring Boot 4.1.2 (Jackson 3, `tools.jackson.*`; JSON annotations remain `com.fasterxml.jackson.annotation`), and Maven 3.9.16 through Maven Wrapper 3.3.4.

#### Scenario: Build toolchain

- **WHEN** the project is built
- **THEN** it SHALL use the Maven wrapper and the declared Java and Kotlin versions.

### Requirement: Runtime frameworks

`users`, `chats`, and `messages` SHALL use Spring MVC. `notifications` SHALL use Spring WebFlux with Kotlin coroutines. `mail-sender` SHALL use Spring MVC, Spring Mail, and Spring Data Redis.

#### Scenario: New web endpoint

- **WHEN** a change adds an endpoint to `users`, `chats`, or `messages`
- **THEN** it SHALL use Spring MVC.

### Requirement: Supporting libraries

The backend SHALL use ShedLock 7.10.1, `java-uuid-generator` 5.2.0, Jakarta Mail API 2.1.5, and `loki-logback-appender` 2.0.3.

#### Scenario: Scheduled jobs

- **WHEN** a scheduled job needs a distributed lock
- **THEN** it SHALL use ShedLock.

### Requirement: Persistence stack

Services that own data SHALL use Spring Data JDBC, PostgreSQL 14, and Liquibase XML migrations. Entity ids SHALL be UUID v7 generated by `IdGenerationBeforeConvertCallback`.

#### Scenario: New entity

- **WHEN** a new entity is persisted without an id
- **THEN** the common id callback SHALL assign a UUID v7.

### Requirement: Messaging and cache stack

The system SHALL use Kafka 7.8.0 (Confluent images) for asynchronous messaging and Redis 7.4.2 for mail idempotency.

#### Scenario: Local infrastructure

- **WHEN** the local Docker Compose stack runs
- **THEN** it SHALL provide Kafka 7.8.0 and Redis 7.4.2.

### Requirement: Observability stack

The services SHALL expose Actuator and Prometheus metrics and SHALL use Micrometer Tracing with Brave. Local observability SHALL use Loki 3.5.3 and Grafana 12.1.0.

#### Scenario: Metrics endpoint

- **WHEN** a service is running
- **THEN** its Actuator metrics SHALL be available.

### Requirement: Test stack

Tests SHALL use Kotest 6.2.6, MockK 1.14.11, JUnit Platform, and Testcontainers 2.0.5 where infrastructure is required.

#### Scenario: Unit test

- **WHEN** a test covers pure logic
- **THEN** it SHALL run without Docker.

### Requirement: Test infrastructure

Test modules SHALL use `common-test/SpringAwareKotestConfig` (Kotest `SpringExtension`) and a module-local `src/test/resources/kotest.properties`. Infrastructure tests SHALL use Testcontainers 2 and Spring Boot 4 test modules. Test fixtures SHALL live under `src/test/resources/it/**` or `src/test/resources/repository/**`. All tests SHALL run in the `test` source set; no separate integration-test profile is configured.

#### Scenario: Repository test

- **WHEN** a test needs SQL fixtures
- **THEN** the fixtures SHALL live under `src/test/resources/repository/**`.

```kotlin
fun Arb.Companion.userEntities(
    ids: Gen<UUID?> = Exhaustive.of(null),
): Arb<UserEntity> = Arb.bind(ids, Arb.string()) { id, name -> UserEntity(id, name) }
```

```kotlin
class MediaMetaGens(
    val ids: Gen<String> = Arb.string(1..8),

    Arb.bind(fieldGens.ids) { id -> MediaMeta(id) }
```
