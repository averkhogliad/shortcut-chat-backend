# Proposal

## Why

`users` and `chats` each carry a near-identical copy of the transactional-outbox machinery (service, handler, cleaner, message, entity, repository, header helpers, scheduled wiring). The copies already drift: `chats` has a `key` field and `@Transactional(propagation = MANDATORY)`, `users` lacks `key` and uses `REQUIRED`. Several files carry `TODO: Must be moved to some common transactional-outbox lib`, and the empty `tx-outbox/` directory is the reserved home for it. Consolidating into reusable modules removes the duplication, locks the stronger `MANDATORY` guarantee for both services, and moves our routing/header conventions out of the core into a starter customization layer. The shape and operational behavior follow the reusable outbox library + starter pattern documented in the `mp-investment-money-box-core-outbox` READMEs and implementation report: claim/lease state machine, retry/backoff, dead-letter, cleanup retentions, lease recovery, a publisher SPI with a default KafkaTemplate-backed implementation, a dedicated task scheduler, and outbox metrics.

## What Changes

- Introduce two new Maven modules: `tx-outbox` (core) and `tx-outbox-starter`.
- `tx-outbox` (core) is a Spring-neutral, domain-agnostic outbox library: `OutboxWriter` (write in the same transaction), `OutboxRelay` (claim, publish, retry, dead-letter), `OutboxPublisher` (transport SPI), `OutboxCleaner` (terminal-record cleanup by retention), `OutboxDao` (`JdbcClient`), and the shipped `message_outbox` schema artifacts (SQL + Liquibase). The core owns state transitions `NEW/CLAIMED/RETRY_WAIT/PUBLISHED/DEAD`, claim/lease (`FOR UPDATE SKIP LOCKED` + `lease_owner`/`lease_until`), retry with exponential backoff and `maxAttempts` → `DEAD`, and lease recovery. The core has **no** knowledge of message `type`, `version`, route resolution, the `X-Event-*` header conventions, or any `OutboxRouter`/`OutboxHeaderProvider` SPI — it just writes, claims, publishes, and cleans what it is given.
- `tx-outbox-starter` depends on the core and provides all customization and runtime wiring as beans: `TxOutboxProperties` binding (`tx-outbox.*`), `OutboxRouter` (type -> route -> topic), `OutboxHeaderProvider` (the five standard headers from `system/kafka-messaging` plus per-route static headers; the `X-Event-*` constants live here), `OutboxEmitter` facade (`emit(type, version, key, bodyPayload)` -> resolve route + headers -> build `OutboxEntry` -> `OutboxWriter.write`), the default `KafkaTemplateOutboxPublisher` (overridable via an `OutboxPublisher` bean), a dedicated `outboxTaskScheduler`, relay/cleanup scheduling, inline lease recovery before each relay cycle, activation conditions, and outbox metrics (Micrometer, fallback `SimpleMeterRegistry`). `users` and `chats` inject `OutboxEmitter`.
- All starter beans are registered `@ConditionalOnMissingBean`, so a consumer can override the router, header provider, emitter, publisher, or any core bean.
- The starter is active only when `tx-outbox.enabled=true` and `JdbcClient`/`ObjectMapper` are present and an `OutboxPublisher` is available.
- The `message_outbox` schema becomes `id, topic, key, body JSONB, headers JSONB, created_at, published_at, state, lease_owner, lease_until, retry_count, next_attempt_at` (no `type`/`version`). The core ships the canonical SQL + Liquibase changelog; a consumer either includes the changelog (fresh create) or drops the transient old-schema table before including / copies the SQL as a reference.
- `users` and `chats` delete their duplicated outbox code (including `OutboxMessageEntity` and `OutboxMessageRepository`) and depend on `tx-outbox-starter`; they call `OutboxEmitter.emit(...)` instead of `outboxService.save(...)`. No externally observable Kafka event or payload change.
- `messages` is unchanged: it keeps direct publish after commit without an outbox, per existing guarantee.
- **BREAKING** (build-only + guarantee): `.agents/rules/architecture/module-boundaries.md`, `openspec/specs/system/architecture/spec.md`, and `openspec/specs/system/runtime-guarantees/spec.md` are updated to permit `users` and `chats` to depend on `tx-outbox-starter` (in addition to `common`), define `tx-outbox`/`tx-outbox-starter` as non-service library modules owning no database, and replace the "mark published without Kafka acknowledgement" guarantee with at-least-once delivery via claim/lease, retry to `DEAD`, lease recovery, and retention cleanup.

## Capabilities

### New Capabilities

- `system/tx-outbox`: contract for the shared transactional outbox — generic `JdbcClient`-backed core (`OutboxWriter`, `OutboxRelay`, `OutboxPublisher` SPI, `OutboxCleaner`, `OutboxDao`) with claim/lease state machine (`NEW/CLAIMED/RETRY_WAIT/PUBLISHED/DEAD`), retry/backoff, dead-letter, lease recovery, terminal cleanup retentions, `JSONB` payload/headers, and the shipped `message_outbox` schema artifacts; starter-provided per-service channels/routes configuration, consumer-overridable route resolver, customizable event headers via an `OutboxHeaderProvider` SPI, default `KafkaTemplate`-backed publisher, dedicated scheduler, activation, and outbox metrics.

### Modified Capabilities

- `system/architecture`: `tx-outbox` (core) and `tx-outbox-starter` are added as non-service build modules owning no database; `users` and `chats` SHALL depend on `common` and `tx-outbox-starter`; `tx-outbox-starter` SHALL depend on `tx-outbox` and `common`; `tx-outbox` SHALL depend on `common`. The core SHALL hold no domain-specific routing or header conventions; the starter SHALL provide them. The `message_outbox` table schema is provided by `tx-outbox` and applied by each service through its own Liquibase master changelog (or copied as a reference).
- `system/runtime-guarantees`: the outbox delivery guarantee changes from "mark published without waiting for Kafka acknowledgement" to at-least-once delivery via claim/lease, retry with exponential backoff to a `DEAD` state, expired-lease recovery, and retention cleanup of terminal records.

## Impact

- New modules: `tx-outbox/` (core) and `tx-outbox-starter/` (each `pom.xml`, `src/main/kotlin`, `src/main/resources`, `src/test/kotlin`); added to root `pom.xml` `<modules>`.
- `users` and `chats`: remove `outbox/OutboxService.kt`, `outbox/OutboxHandler.kt`, `outbox/OutboxMessage.kt`, `outbox/OutboxCleaner.kt`, `core/persistence/entity/OutboxMessageEntity.kt`, `core/persistence/repository/OutboxMessageRepository.kt`; remove `config/ScheduleConfig.kt` outbox wiring; add `tx-outbox-starter` dependency; switch from `outboxService.save(...)` to `OutboxEmitter.emit(type, version, key, bodyPayload)`; declare `tx-outbox.*` properties in `application.yaml`.
- `users` and `chats` DB: old `message_outbox(id, type, version, key, body bytea, created_at, published_at)` is replaced by `message_outbox(id, topic, key, body JSONB, headers JSONB, created_at, published_at, state, lease_owner, lease_until, retry_count, next_attempt_at)`. Outbox is transient, so the old table is dropped and recreated from the shipped changelog (or the SQL is copied as a reference).
- Tests: core outbox unit/DAO/integration tests move to `tx-outbox`; starter customization tests (properties binding, router, header provider, emitter, publisher, auto-configuration, scheduling, metrics, consumer-overrides-default) live in `tx-outbox-starter`; `ChatServiceTest` and `UserServiceTest` switch to mocking `OutboxEmitter`.
- `messages`, `notifications`, `mail-sender`: no change.
- Project Rule `.agents/rules/architecture/module-boundaries.md` updated to remove the "`tx-outbox/` is a future library, do not create it in a local task" prohibition and to record the new module boundary and the core/starter split.
