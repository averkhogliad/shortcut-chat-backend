# AGENTS.md

Инструкции по работе агента в backend-проекте `shortcut-chat`. Обязательные нормы — в `.agents/rules/` и `.agents/procedures/`, определения системы — в `openspec/specs/`.

## Контекст

1. Перед архитектурным анализом, изменением backend-кода или проектированием тестов прочитай `.agents/context/backend.md`.
2. Затем — применимые Rules из `.agents/rules/index.md`. Rules обязательны.
3. Затем прочитай релевантную спецификацию из `openspec/specs/`.

Не читай все документы заранее. Выбирай по области задачи.

## Specs

- `openspec/specs/system/architecture/spec.md` — модули, зависимости, владение данными, sync/async-потоки, outbox.
- `openspec/specs/system/rest-api/spec.md` — REST, DTO, статусы, пагинация, ошибки, identity, SSE.
- `openspec/specs/system/kafka-messaging/spec.md` — топики, события, заголовки, payload, сериализация, consumer'ы.
- `openspec/specs/system/runtime-guarantees/spec.md` — транзакции, outbox, direct publish, Redis, ограничения доставки.
- `openspec/specs/platform/stack/spec.md` — стек, build, test infrastructure.

Главные Specs — источник истины для ожидаемого поведения. Baseline Specs созданы при миграции документации как разовое исключение; дальнейшие изменения поведения оформляй через OpenSpec change, не прямой правкой Specs.

## Расхождения

- Rule — ограничение для агента.
- Spec — ожидаемое поведение системы.
- Код — текущий факт.

При конфликте остановись, зафиксируй вопрос и не выбирай сторону молча.

## Порядок работы

1. Исследуй задачу и затронутый код.
2. Составь план: файлы, операции, риски, проверки.
3. Запроси подтверждение по глобальному `confirmation.md` и жди явного согласия.
4. Реализуй только согласованный объём.
5. Перед сборкой, тестами, миграциями и git-мутациями запроси отдельное подтверждение.
6. Отчитайся: изменённые файлы, выполненные проверки, результат.

## Документация

- Новую норму добавляй в Rule.
- Новое определение поведения — в Spec через OpenSpec change.
- Domain Profile не превращай в копию Specs.
- Не дублируй содержимое: ссылайся на источник.
- Команды проверки и выбор проверок — в `.agents/procedures/verification.md`, не в Specs.

## Git и проверка

- Перед правкой проверь `git status` и diff целевых файлов.
- Сохраняй незакоммиченные изменения. Не перезаписывай файл, не прочитав его.
- Не коммить без явной просьбы.
- Не трогай несвязанные файлы и не исправляй техдолг в локальной задаче.
- Проверки выбирай по `.agents/procedures/verification.md`.
